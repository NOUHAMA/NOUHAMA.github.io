Data Pipeline Project

End-to-end analytics pipeline built with SQL, Snowflake, and dbt, covering ingestion, transformation, testing, and data modeling.

Data Model & Architecture

Star schema centered on FACT_SALES and connected to multiple dimension tables for customer, product, order, and geography analysis.

Pipeline Overview

Data imported from Kaggle was first loaded into Snowflake, then transformed with dbt through staging, intermediate, and mart layers. The pipeline was designed to ensure data quality, consistency, and clear business-oriented reporting.

SQL Snowflake dbt

1. Data Ingestion in Snowflake

The first step of the pipeline consisted of loading the raw dataset into Snowflake. This ingestion layer created the foundation for the rest of the transformation workflow, enabling structured storage, scalable querying, and integration with dbt models.

2. dbt Project Configuration

The dbt_project.yml file defines the structure of the project and controls how models are organized across staging, intermediate, and mart layers. It also helps standardize schemas, materializations, and the general project setup.

3. Source Metadata

Source metadata was defined to document raw tables and apply data quality checks such as unique and not_null tests. This layer makes the project more reliable and easier to maintain by validating key business entities directly from the source.

Staging Layer

Raw data is cleaned, standardized, and prepared for transformation.

Intermediate Layer

The intermediate layer combines and enriches staged data into reusable transformation models that support downstream finance and marketing marts.

Mart Layer

The mart layer organizes the final business-ready models into finance and marketing domains, making them easier to use for reporting, KPI analysis, and decision-making.
